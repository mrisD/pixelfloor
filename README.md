# PixelFloor · 平面像素画生成器

把一张图片用 **64 色方块**铺在**地面**上，做成平面像素画。

* **MC 版本**：1.21.4
* **加载器**：Forge 54.1.18
* **类型**：客户端模组（`clientSideOnly = true`）
* **作者**：mrding

---

## 为什么要平铺在地面

立成一堵墙时，画幅高度受**世界高度**限制——主世界只有 384 格（Y −64 ~ 320），
实际能用的更少。所以"立墙"方案的纵向分辨率上限很低。

铺在地上就绕开了这个限制：**高度只占 1 格**，分辨率只取决于水平距离，
而水平每个轴有 3000 万格。256×256 甚至更大都没问题。

| 方案 | 高度占用 | 分辨率上限 |
|---|---|---|
| 立墙（上一个模组） | 受世界高度限制（约 300 格） | 纵向约 300 格就到顶 |
| **平铺地面（本模组）** | **1 格** | **仅受水平距离限制** |

## 64 色调色板

| 类别 | 色数 | 特点 |
|---|---|---|
| 羊毛 wool | 16 | 不透明，便宜 |
| 混凝土 concrete | 16 | 不透明，饱和度高，负责鲜艳区域 |
| 陶瓦 terracotta | 16 | 不透明，低饱和，负责"灰扑扑"的中间色 |
| 染色玻璃 stained_glass | 16 | 半透明，颜色会受下方方块影响 |

颜色取自**游戏本体 jar 里的方块贴图平均色**，不是凭"标准染料色"估的——
官方贴图带细微噪点和明暗层次，用标准色会有肉眼可见偏差。

### 效果对比（在真实照片的 20000 个像素上实测）

| 调色板 | 最坏色差 ΔE | 平均色差 ΔE |
|---|---|---|
| 16 色羊毛（立墙模组） | 22.06 | 11.18 |
| 48 色（不含玻璃） | 18.09 | 9.24 |
| **64 色（本模组）** | **17.16** | **8.08** |

平均色差改善 **28%**。陶瓦专门覆盖低饱和中间色（肤色、岩石、木材、植被），
混凝土覆盖高饱和区，两者互补。

### 关于染色玻璃

玻璃是半透明的，**实际看到的颜色取决于它下面的方块**。本模组给的 RGB 是按
浅色底测的，所以：

* 铺在石头/泥土上时，玻璃颜色会比预期暗一些
* 想让玻璃颜色准，可以先在地面铺一层白色混凝土或雪再放玻璃

不想要玻璃可以在界面里关掉，或直接改 `palette_floor.json`。

## 安装

### 1. 编译

需要三个 JDK（**ForgeGradle 7 的硬性要求**）：

| JDK | 用途 |
|---|---|
| **JDK 21** | 构建用，Minecraft 1.21.4 的编译目标 |
| **JDK 25** | ForgeGradle 7 内部 mavenizer 工具的运行环境 |
| **JDK 8** | 处理 Mojang 官方 mappings |

外加 **Gradle 9.3.1**。`settings.gradle` 里配了 foojay-resolver，缺的 JDK 会自动下载。

Windows 上直接双击 **`build.bat`**，产物在 `build\libs\`。

### 2. 装进游戏

把 `build\libs\pixelfloor-1.0.0.jar` 放进 mods 目录：

* **没有版本隔离**：`%APPDATA%\.minecraft\mods\`
* **开了版本隔离**（PCL2 / HMCL 常见）：`.minecraft\versions\<版本名>\mods\`

`安装.bat` 会自动探测两种情况并复制、校验。

### 3. 使用

进存档（**要开作弊**，铺设依赖指令），然后：

```
/pixelfloor
```

界面打开 → 左上角点目录（图片/下载/桌面…）→ 点一张图 → 调画幅 → 点「▶ 开始铺设」。

## 指令

| 指令 | 说明 |
|---|---|
| `/pixelfloor` | 打开图形界面 |
| `/pixelfloor load <路径>` | 用当前设置转换指定图片 |
| `/pixelfloor info` | 打印尺寸、色差、用色统计 |
| `/pixelfloor palette` | 在聊天栏列出 64 色调色板 |
| `/pixelfloor build` | 在你面前铺设 |
| `/pixelfloor cancel` | 取消还没发完的指令 |

## 工作原理

```
图片文件
  │  ImageIO 读取
  ▼
旋转/翻转/裁剪/缩放（双三次）→ 画幅大小的缩略图
  │  逐像素
  ▼
CIEDE2000 匹配最近的方块（64 色中选一个）
  │
  ├─► 预览图（界面里的"俯视效果"）
  └─► 逐行合并成 /fill ──► 逐 tick 发送
```

### 坐标映射

```
图片 col (0 = 最左)  ->  世界 X 递增
图片 row (0 = 最上)  ->  世界 Z 递增（远离玩家）
```

方向推导：玩家低头看图时视线方向是 −Y，"屏幕上方"是面朝方向 `f`，
所以屏幕右方 `= cross(视线方向, 上方) = cross(−Y, f)`。
代入面朝南 `f=(0,0,1)` 得屏幕右方 `= (−1,0,0) = 西`，
而 `Direction.SOUTH.getCounterClockWise()` 正好是 west。

**注意这和"立墙"模组的结论相反**（立墙用 `getClockWise`），照抄会左右镜像。
这一点已用投影探针在四个朝向下逐一验算过。

### 地面处理

1. 从玩家所在格向下找第一个实心方块（跳过水和空气），在它上面一格铺设
2. 铺设前先在整幅画下方垫一层石头（默认 `minecraft:stone`），防止地形起伏造成悬空

垫底可以在界面里关掉，也可以在 `config/pixelfloor/settings.properties` 里改材质。

### 性能与速度档位

* 颜色匹配带 5 位 RGB 缓存表（32768 格），避免逐像素重复算 CIEDE2000
* 逐行合并同色方块：合并后条数完全取决于图片内容——照片相邻像素颜色变化快，
  平均每条 `/fill` 只覆盖几格；色块图则一条能覆盖上百格
* 图片读取和转换在后台线程，界面不阻塞

界面上的 **速度** 按钮可以循环切换每 tick 发送的指令条数：

| 档位 | 条/秒 | 说明 |
|---|---|---|
| 6（默认） | 120 | 最稳，适合大画幅或联机 |
| 12 | 240 | 速度与稳定的平衡点 |
| 24 | 480 | 单人游戏推荐上限 |
| 48 | 960 | 最快，可能卡顿，联机可能被判刷屏 |

界面会实时显示**预计指令数和耗时**，例如 300×578 的照片画幅约需 34500 条指令：
6 条/tick 约 4.8 分钟，24 条/tick 约 72 秒。

> 为什么不能无限快：`/fill` 的方块更新会挤在同一刻，发太快会卡顿；
> 联机时还可能被反作弊判定为刷屏。

## 已知限制

* **染色玻璃颜色受下方方块影响**（见上文）
* **Java 版没有 16 色地毯**，所以无法用"坐垫"做调色板——只有 `pale_moss_carpet`
  一种。本模组改用混凝土与陶瓦补足色域
* **不用带釉陶瓦**：它的贴图是带箭头花纹的方块，颜色只占一部分面积，
  取平均色会严重失真
* **需要作弊/OP**：铺设靠 `/fill` 指令
* **方块数建议不超过 512×512**：再多指令量会明显拖慢游戏
